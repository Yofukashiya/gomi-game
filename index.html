if (grounded && pressed) jump();          // 素の実装
if (timeSinceLeftGround < COYOTE) canJump = true;  // 崖の許し

結論（本人の言葉）：実装は驚くほど速い。でも 「面白いゲームを設計することは、いまも人間固有のスキル」。

AIが自分でテストして、自分のバグを見つけた 実例2件（raccoon-heist の作業ログより）

🐛 スマホで主人公が見えない DPR bug

Playwrightで 390×844 / DPR 2 のスマホを再現して発見。

renderer.setSize() の後に canvas.style.cssText を代入 → Three.jsが設定したwidth/heightを上書き。DPR≥2の実機だとcanvasが2倍サイズで描画され、左上1/4しか見えない。

PCでは DPR 1 なので完全に再現しない。＝人間の手動確認では見逃すタイプ。

🐛 「NIGHT 2 ➜」ボタンが押せない CSS class collision

クリア→次ステージまでの通し操作を自動化して発見。

勝利画面の星表示に付けた class="stars" が、タイトル画面の全画面 .stars のCSSと衝突。透明な要素が画面全体を覆ってクリックを吸っていた。

クラス名の衝突。レビューでもすり抜けやすい。

AIに「作らせる」だけでなく 「確かめさせる」。スクショ・自動操作・ログを渡すと精度が変わる。

素材もAIが作る 画像生成 & 3Dモデル（実物が回っています）

① 画像生成API：絵柄を揃えるコツ

# 全素材に同じ STYLE を前置きする
STYLE = ("Seamless tileable texture, top-down flat "
  "orthographic view, no perspective, even lighting, "
  "video game texture map, stylized low-poly game art, "
  "moody nighttime palette with cool blue tones. ")

TEXTURES = {
  "grass": "Dark night-time lawn grass ...",
  "fence": "Old wooden fence planks ...",
  "metal": "Galvanized trash can surface ...",
}
gen(STYLE + TEXTURES[name])   # → 512px JPEG を commit
  • STYLE前置きで7枚の絵柄が揃う（バラバラ問題の対策）
  • ビルド時に1回生成して静的ファイルとしてcommit。公開後はAPIを呼ばない＝落ちない・無料
  • テキスト→3Dの専用ツールもある（Meshy など）
  • 商用は利用規約・著作権・一貫性を必ず確認

② 3Dモデル：形をコードで書かせる

AIの弱点と、線引き

  

    
01
自信満々の誤り Hallucination
もっともらしく間違える。動くコードほど危ない。

    
02
権利・ライセンス Licensing
画像・音・コードの利用条件。商用は特に。

    
03
一貫性 Consistency
キャラ・世界観・命名がバラける。STYLE前置きや規約で対策。

    
04
技術的負債 Technical Debt
理解せず積むと、後から直せない山になる。

  

  

    
👍 任せやすい
  • 小さい機能の実装・下書き
  • エラー原因の説明、別案の提示
  • テスト観点の洗い出し・自動テスト
  • ローカライズ／文章のたたき台
  • 素材のラフ・方向性の確認

    
✋ 人間が持つ
  • 面白いかどうかの判定
  • 数値の最終調整（手応え）
  • 何を作らないかの決定
  • 権利・公開の責任
  • コードを理解しておく責任
